# Семейства моделей и ансамблевый поиск

Лимит `max_candidates` относится к обычным родительским гипотезам: максимум две
за цикл. Гипотеза с `kind=family` содержит до трёх исполняемых вариантов.
`model_family=gradient_boosting` проверяет доступные LightGBM, CatBoost и XGBoost;
другие семейства указывают `family_tools`. Каждый вариант имеет устойчивый ID,
собственный код и артефакты. `SearchGroupPlan` объединяет их с родительской гипотезой.
Старый одиночный план соответствует группе из одного варианта.

По умолчанию `initial_boosting_sweep=true`: первый цикл supervised-задачи обязательно
проверяет доступные LightGBM, CatBoost и XGBoost, даже если генератор предложил одну
библиотеку. Режим `initial` оформляет одну семью с тремя фиксированными стартовыми
конфигурациями. Каждый backend получает собственную предобработку и исходники,
а фолды, train/holdout, метрика и seed остаются общими. Workers запускаются одной
партией; CPU/RAM делятся с учётом `max_workers` и доступной ёмкости. Например, при
6 CPU и 4 GiB для workers три модели получают по 2 CPU и примерно 1.33 GiB. При
недостатке ресурсов та же очередь исполняется меньшим числом параллельных workers.
Неподдерживаемые/отсутствующие библиотеки и ошибки каждого варианта записываются
отдельно, не удаляя успешные модели. Все прошедшие machine gate варианты сохраняются
в пул компонентов независимо от места в сравнении. Первый успешный baseline
сохраняет CSV; HPO победителя семьи и feature engineering начинаются после стартовой
партии. Дополнительная генерация других гипотез остаётся следующим циклам.

`initial_boosting_sweep=false` сохраняет прежний порядок: первый вариант baseline
публикует CSV до подготовки остальных. Режим `baseline` откладывает остальные варианты,
а `alternatives` планирует их все из сохранённой партии гипотез. Старые session при
resume сохраняют прежнюю политику, если в них ещё нет нового флага.
В следующих циклах режим `all` также сохраняет все
выбранные варианты семейства: первый принятый план не завершает обработку группы.
Варианты сравниваются на одинаковом внутреннем протоколе. HPO получает только
победитель семейства; неудача подбора не уничтожает стартовый результат. Внешний
holdout оценивает победителя группы; быстрый baseline является исключением.

Со второго цикла `ensemble_agent` предлагает отдельную композицию двух–трёх
прошедших machine gate одиночных моделей из завершённых предыдущих циклов.
Проигравшие варианты доступны наравне с чемпионами. Пул не содержит рекурсивных
ансамблей и native AutoML с непроверенным frozen refit. Оценки разных split
передаются как история, а не сопоставимый рейтинг. Агент может объяснённо пропустить
поиск. Невалидный JSON-ответ ансамбля получает обратную связь и повторяется в том же
окне роли, до `max_attempts`; лишнее поле не должно молча удалять всю попытку поиска.
`ensemble_search_enabled=false` отключает эту дополнительную ветку;
`ensemble_agent_seconds` ограничивает роль только при включённых таймаутах.

Planner оформляет задание, кодер создаёт входной модуль для `sdk.FrozenEnsemble`.
Источники копируются в `components/` и защищаются хешами и запретом записи кодером.
Регрессия проверяет среднее, медиану, обучаемый блендинг и Ridge-стекинг;
классификация — среднее вероятностей, блендинг и LogisticRegression-стекинг.
Multilabel использует отдельную логистическую метамодель для каждого выхода.
Только победитель внутреннего сравнения рецептов оценивается на внешнем holdout.

Каждый компонент заново обучается со своими preprocessing и политиками цели/весов.
Обучаемые веса и метамодели используют трёхфолдовые OOF-прогнозы внутри текущего
обучающего split; внутренний validation и внешний holdout не используются для их
обучения. Группы и дубли из FitContext остаются непересекающимися. Недостаток
групп/классов приводит к отказу дорогого рецепта; простые комбинации сохраняются.
Веса неотрицательны и нормированы, число попыток ограничено `hpo_max_trials`.
Эти попытки обучения весов не считаются выполненными HPO trials обычной гипотезы.

При refit фиксируются состав, метод и гиперпараметры. Обучаемые веса и метамодель
переобучаются допустимыми данными без нового выбора рецепта. Артефакт сохраняет
исходники, модели, порядок классов и состояния политик; для независимого inference
можно загрузить `sdk.load_module(artifact/'source').load_candidate(artifact)`.

Очередь сохраняет приоритет переобучения чемпиона, текущие CPU/RAM и `max_workers`.
Простые рецепты стоят перед дорогими; при включённых таймаутах учитываются OOF,
refit и прогнозирование. Дополнительная гипотеза не создаёт дополнительный worker.
Настройка таймаутов по умолчанию остаётся выключенной.

В experiments.sqlite3 сохраняются `search_group`, `search_group_progress`,
`search_group_result`, `training_plan`, `component`, `ensemble_proposal`,
`search_group_budget`, `ensemble_planning_progress` и `ensemble_planning`. Анализ цикла содержит
`search_groups`: варианты, победителя, причины пропусков и ошибки. Resume использует
завершённые эксперименты и исходные лимиты. Успешность механизма не требует
обязательного улучшения метрики ансамблем.
