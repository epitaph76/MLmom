# Группы моделей и рецептов — контракт v4

Агенты выбирают модели, семейства, компоненты, методы ансамбля и бюджеты.
Контроллер создаёт содержащую группу со списком вариантов. Принадлежность не является
самостоятельным агентским решением и не проверяется сравнением разных строковых меток.

Planner получает схему PlannerPlan. В ней нет search_group_id, search_group_kind и
parent_hypothesis. Старые ответы с этими полями принимаются без использования подсказок
принадлежности; остальные поля эксперимента проходят обычное структурированное чтение.
Семантический Plan validator сохраняет право отказа по содержанию эксперимента.

SearchGroupPlan владеет hypothesis/kind/variants. Его варианты получают производные
поля HypothesisPlan для исполнения и сохранения. Одиночные гипотезы имеют независимые
группы без общего search_group_id; lineage хранится в based_on/based_on_hypothesis_id.
Семейства получают родителя от контроллерского expand_families. Рецепты ансамбля
получают общего родителя до входа в planning graph и до semantic review.

Выбор победителя семейства/рецептов остаётся на внутренней метрике одного протокола.
Внешняя оценка принадлежит выбранному варианту. Первый baseline/refit и другие
правила обучения описаны в AGENT_PIPELINE_V3_RU.md; изменение v4 касается принадлежности
к группам и изоляции локальных ошибок, не модели оценки качества или лимитов ресурсов.

Агент явно выбирает mean/median/weighted/stack. mean/median не получают настройки OOF
или поиска весов. Каждый frozen-компонент сохраняет собственный код, preprocessing,
feature_set и runtime policies. Поиск не добавляет невыбранных методов.

Ошибка одного рецепта сохраняется в ensemble_recipe_failed с методом, причиной и
типом ошибки. Успешные предыдущие и последующие рецепты сохраняются. Явная отмена,
глобальная ошибка API и неисправность worker infrastructure продолжают передаваться
контроллеру, а не маскируются как локальная ошибка рецепта. Resume использует сохранённые
результаты того же контракта; ошибки не запускаются повторно без нового решения.

Текущая session runtime_contract_version=5; см. [оценки времени и замены](ADVISORY_COSTS_AND_REPLACEMENT_RU.md).
После смены контракта нужен новый каталог запуска;
старые trace, модели и результаты сохраняются. Формат модели SDK contract_version=2
остаётся прежним, сохранённые inference-артефакты не мигрируют в активное состояние.
