# Feature agent

Новые запуски выполняют feature-сессию в каждом цикле. При `initial_boosting_sweep=true`
первый цикл запускает её после сравнения стартовых бустингов и HPO победителя.
При отключённом sweep — после первого корректного submission перед HPO одиночного
baseline. В последующих циклах — после переобучения incumbent и выбора моделей/семейств
текущего раунда.
По умолчанию `feature_search_enabled=true`, `feature_max_configurations=6`,
`feature_plateau_limit=3`, `feature_min_delta=0`, `feature_agent_seconds=120`.
Старые session.json без этого флага продолжаются с отключённой веткой. При resume
нельзя менять конфигурацию, данные, исходники, опорную модель или folds.
Лимиты конфигураций и plateau относятся к отдельной сессии и начинаются заново в
следующем цикле. Завершение feature-поиска не отключает его в последующих раундах.

## Роли и порядок

Скилл `feature_agent` включает Hidden Entity & Repeated Observation Discovery:
поиск возможных повторных наблюдений одной сущности по сочетаниям стабильных
атрибутов, даже без явного ID. Совпадение атрибутов рассматривается как гипотеза;
нужны проверка неоднозначности, доступность данных на момент прогноза и защита
валидации от утечек между связанными наблюдениями. Карты сущностей и агрегаты
обучаются внутри training fold; история использует только доступное прошлое.
При отсутствии подтверждающих фактов, безопасного протокола или нужного оператора
агент указывает ограничение в rationale. Это обновление инструкций; операторы
исторических соединений и сопоставления составных ключей в DSL v1 не добавлены.

`feature_agent` получает условие, подтверждённый контракт, измеренный профиль только
внешнего train, срезы внутренних OOF-ошибок и память проверок. Исходный профиль всего
датасета, внешние оценки, holdout residuals и test ему не передаются. Численные
сводки пересчитывает Scheduler worker. Агент предлагает одну связанную группу
операций, удаление группы или завершение поиска. Planner оформляет
`FeatureExperimentPlan` для фиксированной пары; runtime создаёт `HypothesisPlan`
с неизменными исходниками, экспортированными параметрами и policies baseline.

Предобработку по-прежнему пишет preprocessing_agent. SDK добавляет доверенные
признаки после базовой предобработки; генерировать их повторно в preprocessing.py
не нужно. Модельный код не меняется, HPO и early stopping в feature-ветке отключены.
Backend fit-entry provenance проверяет, что модель получила все добавленные колонки.

## DSL v1

Определения `FeatureSpec` и `FeatureSet` находятся в `mlmom/feature_contracts.py`.
Набор содержит до 16 признаков. Операторы принимают имена исходных разрешённых
колонок; произвольные выражения, Python и ссылки на другие derived features отсутствуют.

| op | Аргументы | Поведение |
|---|---|---|
| missing | columns: [x] | Индикатор пропуска |
| log | columns: [x] | Натуральный логарифм положительных значений |
| ratio/difference/product | columns: [x, z] | x/z, x-z, x*z |
| date_part | columns: [x], part | year/month/day/dayofweek/hour в UTC |
| frequency | columns: [category] | Доля категории в training fold; неизвестная — 0 |
| group_count | by: category | Число строк группы; неизвестная — 0 |
| group_mean/std/min/max | columns: [x], by: category | Статистика training fold; неизвестная — глобальная train-статистика |

std использует ddof=0. Некорректные даты, логарифмы, нулевые знаменатели и infinities
дают пропуски. Они заполняются медианой engineered-колонки из training fold; полностью
пустая колонка использует 0. Карты, fallback и медианы сохраняются; transform ничего
не дообучает и не использует состав prediction batch. Все операции сохраняют строки
и порядок. DataFrame сохраняет индекс и категории, sparse дополняется через CSR hstack.

Target, ID, группы, веса и исключённые колонки недоступны как вход DSL. Группировка
по обычной категориальной feature допускается; служебная group_column остаётся закрытой.
Лаги, point-in-time joins, target encoding, embeddings и межтабличные признаки в DSL v1
не входят. Ранее реализованная базовая предобработка сохраняется.

## Проверка и выбор

Во всей сессии используется один внешний split. Для подтверждённой CV сохраняются
её фактические индексы. При основном holdout строятся три внутренних folds только на
внешнем train: KFold, StratifiedKFold либо GroupKFold с учётом групп/дубликатов.
Основной TaskDefinition не меняется. Недостаточные группы/классы дают skipped с причиной.
Сессия поддерживает regression, binary_classification и multiclass_classification с
обычным одиночным baseline и отдельной preprocessing.py.
Опорой служит текущий Champion с уже принятыми признаками: их можно дополнить или
удалить, включая возврат к пустому набору. Если лидирует ансамбль или native AutoML,
используется проверенная одиночная модель текущего раунда, выбранная по внутренней
метрике. При её отсутствии берётся проверенный компонент завершённых циклов, с
приоритетом источников ансамбля. Исторические оценки разных split не ранжируются.
Контроль и предложения всегда заново обучаются на train и folds текущего цикла.

Контрольная конфигурация проходит тот же протокол. Каждый эксперимент проверяет одну
группу относительно текущего принятого набора. Runtime проверяет полный набор folds,
OOF coverage, hashes, execution gate и обязательный full-train refit. Оценки помечаются
`validation_scope=feature`, `feature_inner_cv_mean` и `feature_inner_oof`.

Принятие требует среднего направленного delta > feature_min_delta и положительного
delta минимум на ceil(2K/3) folds **как относительно родителя, так и относительно
исходного baseline**. Положительный, но нестабильный эффект — quarantine; отсутствие
прироста — rejected; ошибка исполнения — failed/непроверено. Проверка констант и
дублей использует только training-части folds и не фильтрует признаки по корреляции с y.

Лимит резервируется до запуска проверки. Ошибки тоже расходуют шесть конфигураций;
они не считаются завершёнными статистическими проверками plateau. Три завершённые
проверки без устойчивого прироста останавливают поиск. Дополнительно ограничено число
предложений: max_configurations * max_attempts. Переименование формулы не обходит память.

После заморозки поиска только лучший устойчивый набор проходит smoke export/recreate
и одну внешнюю оценку. Отказ не запускает перебор других наборов по тому же holdout.
При внешнем улучшении он становится Champion; в первом цикле также входом HPO.
При ансамбле в роли Champion выиграть должен весь одиночный кандидат с новым набором,
а сам ансамбль сохраняет независимые наборы своих компонентов. Внешняя оценка остаётся
текущим сравнительным holdout системы; независимый audit holdout здесь не добавляется.

## Память и перенос

`feature_search/` содержит первую сессию (`initial`, раунд `r1`), а
`feature_search/r2/`, `feature_search/r3/` и далее — независимые сессии следующих циклов.
Каждая содержит folds.json, session.json, request/result каждого worker,
OOF, доказательства и winner-smoke. В experiments.sqlite3 сохраняются feature_session,
feature_set, feature_proposal, feature_experiment_plan, feature_evidence и feature_registry.
Резервирование, proposal и завершённый worker восстанавливаются без повторного обучения.
Предложения, парные планы, evidence и worker ID разделены по сессиям; определение
формулы остаётся общим и неизменным. Повтор той же формулы в новом цикле получает
новые доказательства и не переиспользует старые OOF. Агент видит историю проверок
только своей сессии. Повторное внешнее принятие сохраняется в feature_registry_acceptance,
исходная запись feature_registry не перезаписывается. summary.json содержит все
feature_search_sessions и последнюю сессию в feature_search.
Хеш признаков входит в ModelSpec, backend provenance, HPO identity и сохранённую модель.

Генератор гипотез и Planner видят историю с определениями и причинами. Только набор,
подтверждённый внешней оценкой, попадает в каталог feature_sets. Для новой модели
Planner явно задаёт feature_set_id либо null; runtime подставляет неизменное определение.
HPO и финальный refit сохраняют выбранный набор. Frozen ensemble-компоненты сохраняют
собственные наборы; общий набор поверх ансамбля не поддерживается.

Память ограничена текущим запуском и resume. Дополнительных библиотек и внешнего
feature store нет. Проверки: tests/test_feature_engineering.py и tests/test_feature_session.py.
