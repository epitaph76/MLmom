# Эксперимент: агенты и технический минимум

Ветка `codex/agent-first-minimal-checks` физически удаляет методологические machine gates.
Исходное состояние проекта со всеми локальными правками сохранено коммитом `78f5409`.
Строгая реализация доступна в истории Git; переключателя режимов нет.

## Рабочий цикл

Inspector вычисляет профиль. Разведчик подтверждает исполнимую постановку и исследует CSV.
Context agent готовит смысловой brief, генератор предлагает гипотезы, Planner оформляет планы.
LLM plan_validator самостоятельно разрешает исполнение или возвращает замечания на исправление.
Python проверяет только технические условия и доступный бюджет.

Агенты предобработки и модели пишут отдельные модули. Проверка исходника проверяет синтаксис
и фабрики; списков допустимых импортов и автоматического переписывания Python больше нет.
Smoke fit/predict/save/load доступен кодеру по запросу и не является условием допуска.

Workers выполняют внутреннюю validation/HPO и refit. Сохранённая модель загружается для
прогноза, метрики вычисляются по реальным прогнозам. Champion выбирается по измеренной
метрике на текущем внешнем split. Полный refit на размеченных данных выпускает CSV каждого цикла.
Feature agent продолжает поиск признаков; улучшение внутреннего среднего достаточно для
отбора, дополнительного порога устойчивости нет. Ансамбли обучают компоненты и OOF как прежде.
Result validator даёт рекомендации и не блокирует Champion или CSV.

## Оставшиеся проверки

- Обязательные исполнимые поля/типы, используемые файлы, колонки, ссылки на компоненты.
- Границы каталогов и инструментов, раздельные данные train/holdout, исключение target,
  отсутствие LLM-ключей в worker. Статический анализ исходника не является песочницей.
- CPU/RAM, lifecycle процессов, ограниченные попытки и заданные бюджеты. Таймауты по-прежнему
  выключены по умолчанию и включаются явной настройкой.
- Размеры, допустимые значения и конечность прогнозов/метрик; колонки, ID и порядок CSV.
- Целостность сохраняемых файлов и состояние resume, чтобы не подменять уже выполненную работу.

## Интерфейсы и диагностика

Кандидат реализует fit, predict, save и фабрики create_candidate/load_candidate.
export_model_params необязателен: используется его JSON-объект либо параметры выполненного trial.
Полнота/эквивалентность экспорта не проверяются. fitted_components не требуется.
ModelSpec остаётся описанием сохранённых параметров и политик, а не доказательством исполнения.

Перехват fit, аудит estimator, обязательный export/recreate и условия допуска по execution_report
удалены. Старые optional-поля отчётов читаются; новые запуски не генерируют фиктивных passed-отчётов.
Наблюдения, цитаты и приоритеты сохраняют суждение агентов без детерминированной сверки.
Неизвестные пояснения агентских ответов сохраняются в agent_notes и не исполняются как настройки.

Сохраняются исходники/версии, параметры, метрики, решения агентов, ошибки и полные traceback.
Новые проверки добавляются после разбора конкретного сбоя с воспроизводящим примером.
Эксперименты используют новые run-каталоги; активные прогоны между версиями не переносим.

## Проверка изменений

Полный unittest discover и упаковка проверяют текущую ветку. Интеграционные тесты используют
подставной LLM и настоящее локальное обучение, prediction, refit, CSV и resume.
Прогоны с платным LLM не являются частью этой проверки.
