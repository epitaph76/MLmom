# Архитектура

`Pi Web → Pi session → MLmom extension → HTTP → Python backend / Research service`.
Pi отвечает за LLM, контекст и вызовы инструментов; собственного агентного цикла MLmom нет.

| Компонент | Сейчас | Позже |
|---|---|---|
| Pi Web | Готовая npm-зависимость, штатный интерфейс | Обновление совместно с пакетами Pi |
| Extension | 8 инструментов, валидация HTTP-ответов, отмена | Новые ML-возможности через тот же backend |
| Backend | Health, capabilities, пустая история; остальные операции — 501 | Profiler, проверка рецептов, Runner, Evaluator, Controller |
| Research mock | Асинхронные задания в памяти, синтетические карточки | Сервис тиммейта с тем же HTTP-контрактом |
| Workspace | Настраиваемый каталог | Код, данные и артефакты экспериментов |
| MLflow / Research KB | Только настройки подключения | Хранение моделей и найденных знаний |

LLM будет предлагать структурированный рецепт; Python проверит его и построит pipeline. Evaluator и Controller независимо определят качество, допустимость следующего эксперимента и остановку; численные лимиты сейчас не устанавливаются.

## Настройки

Переменные окружения имеют приоритет над `.env`; `.env.example` содержит значения по умолчанию. Каталоги разрешаются относительно корня репозитория; URL и пути передаются процессам явно.

| Переменные | Назначение |
|---|---|
| `ROUTERAI_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | Ключ из окружения, endpoint и модель |
| `PI_CODING_AGENT_DIR` | Локальная конфигурация и сессии Pi, по умолчанию `.local/pi-agent` |
| `PI_WEB_HOSTNAME`, `PI_WEB_PORT` | Адрес Pi Web |
| `BACKEND_HOST`, `BACKEND_PORT`, `BACKEND_URL` | Bind backend и URL для клиентов |
| `RESEARCH_HOST`, `RESEARCH_PORT`, `RESEARCH_URL` | Bind mock и URL поиска для клиентов |
| `RESEARCH_MODE` | `mock` запускает заглушку; `external` подключает внешний сервис |
| `HTTP_TIMEOUT_MS`, `HTTP_GET_RETRIES` | Таймаут каждого HTTP-запроса и число повторов GET |
| `RESEARCH_POLL_INTERVAL_MS`, `RESEARCH_POLL_TIMEOUT_MS` | Интервал и срок ожидания поиска; не бюджет экспериментов |
| `RESEARCH_MOCK_DELAY_MS` | Задержка тестового поиска |
| `WORKSPACE_DIR` | Каталог будущих ML-артефактов |
| `MLFLOW_TRACKING_URI`, `RESEARCH_KB_URL` | Зарезервированные точки подключения; сейчас не используются |

Launcher создаёт конфигурацию RouterAI с ссылкой на переменную окружения, без записи самого ключа. Локальные сессии и `.env` исключены из Git; глобальный каталог Pi не требуется.

## Процессы

Launcher запускает сервисы отдельно, проверяет их health и затем запускает поставляемый Pi Web Next-сервер без пересборки. Он проверяет занятость портов и останавливает созданные процессы при сигнале завершения или падении сервиса.

Будущая контейнеризация сможет заменить адреса сервисов и каталоги через окружение; Research API не зависит от общего файлового диска. Backend и mock можно запускать отдельно через `.venv` Python: `python -m uvicorn mlmom.backend:app` и `python -m uvicorn mlmom.research_mock:app` с нужными `--host` и `--port`.

## Ограничения этапа

Research mock теряет задания при перезапуске и не выполняет поиск. Нет исполнения сгенерированного Python-кода, обучения, метрик, сохранения экспериментов и гарантий изоляции процессов обучения.

Pi остаётся обычным локальным агентом с инструментами файловой системы. Готовность инфраструктуры не означает готовность автономного ML-решения.
