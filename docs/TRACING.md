# Трассировка запуска

Полная трасса включена по умолчанию и хранится в `--run-dir`; его путь возвращается в итоговом JSON. Для одного задания удобно задать постоянный каталог:

```bash
python solution.py task.md --run-dir artifacts/task-run
python solution.py task.md --run-dir artifacts/task-run --resume
```

## Файлы и порядок чтения

| Файл | Содержание |
|---|---|
| `trace.md` | Итоговый отчёт: usage по task/role, число событий, хронология и ссылки на payloads. Создаётся при завершении, в том числе при обработанной ошибке. |
| `trace.jsonl` | Живой журнал UTF-8: один JSON-объект на строку, flush после каждого события. |
| `trace_payloads/<sha256>.json` | Полные очищенные данные события: запрос, ответ, аргументы/результат инструмента, тексты скиллов или ошибка. Одинаковые payloads используют один файл; запись выполняется через временный файл и атомарную замену. |
| `trace.sqlite3` | Основной committed-журнал: таблица `trace_events(seq INTEGER PRIMARY KEY AUTOINCREMENT, body TEXT NOT NULL)`, `body` — тот же JSON события. При работающем процессе возможны файлы `-wal`/`-shm`. |
| `experiments.sqlite3`, `checkpoints.sqlite3` | Отдельные контракты ML-экспериментов и состояние LangGraph; они не заменяют трассу API. |

Начните с `summary.json` и `trace.md`, найдите последний успешный этап или `*.failed`, затем откройте соседние payloads. При незавершённом процессе читайте `trace.jsonl`: отчёт может ещё отсутствовать. Для worker также сохраняются `request.json`, `result.json`, `stdout.log`, `stderr.log` в соответствующих подкаталогах runs/checks/probes/inspection/predictions.

## События и связи

Каждая строка содержит `schema_version=1`, `event_id`, `seq`, `run_id`, `task_id`, `timestamp` в UTC ISO 8601, `elapsed_seconds` и `kind`. Контекст добавляет `stage`, `role`, `round_id`, `hypothesis_id`, `candidate_id`, `experiment_id`, когда они известны; у spans есть `span_id` и `parent_span_id`. У инструментов присутствует провайдерский `tool_call_id`, у HTTP-попыток — `attempt`, у ответа — `request_id`, если его вернул провайдер.

Поле `payload` имеет форму `{"path":"trace_payloads/<sha256>.json","sha256":"<sha256>","bytes":123}`. Путь разрешается относительно каталога трассы; SHA256 и размер относятся к очищенному JSON в UTF-8. Полные messages и результаты лежат в payload, краткие поля контекста — в строке события.

- `run.started/resumed`, `stage.*`, `planning.policy` показывают управление запуском.
- `llm.role.*` / `llm.completion.*` охватывают обращение агента, `llm.call.*` — один шаг диалога, `llm.attempt.*` — фактическую HTTP-попытку. Успешный HTTP-ответ ещё может привести к ошибке JSON, schema или лимита токенов; это видно на внешнем span.
- `llm.response` сохраняет возвращённый response до проверки; `llm.provider_error`, `llm.retry_scheduled`, `llm.fallback` объясняют повторы. Payload `llm.attempt.started` содержит фактические messages, tools, model, JSON mode и timeout этой попытки. SDK retries отключены. Клиент не передаёт лимит выходных токенов; старые `llm_max_tokens`, `max_tokens` и переменная `ROUTERAI_MAX_TOKENS` не ограничивают запрос. Если провайдер возвращает `finish_reason=length`, трасса сохраняет ответ и ошибку усечения на стороне провайдера.
- `tool.started`, `tool.result`, `tool.completed` показывают имя, аргументы и полный ToolResult. Ошибка инструмента возвращается как `tool.result` со `status=error`; сам вызов при этом завершился с результатом.
- `skills.started/loaded/completed/failed` сохраняют запрошенные и автоматические скиллы, версии, хеши и полные тексты. `task_analysis.attempt/validation` сохраняют ответы постановщика и результаты проверки каждой попытки.
- `scheduler.admitted/denied/released` показывают CPU, RAM, время, affinity, статус и освобождение слота. События `runtime.*` дублируют очищенные runtime-события из журнала экспериментов.

`run_id` сохраняется в `session.json` и не меняется при resume; task ID трассы определяется входным путём задания и доступен до анализа данных. `TaskContext.task_id` отдельно идентифицирует постановку и данные. Сортируйте события одного журнала по `seq`, связывайте вложенные действия через spans; при resume создаются новые spans, а `elapsed_seconds` отсчитывается заново от открытия sink. Между журналами сравнивайте UTC timestamp и run/task IDs. Один текущий CLI-запуск обрабатывает одну задачу; отдельные запуски требуют разных каталогов.

## Полнота, секреты и восстановление

Трасса сохраняет только фактически полученные поля провайдера. Если ответ содержит reasoning-поле, оно входит в снимок; скрытые рассуждения, которых API не вернул, восстановить нельзя. `reasoning_tokens` показывает счётчик, а не текст reasoning. Usage и cost отсутствующего ответа неизвестны; отчёт не приравнивает их к нулю и не предполагает валюту стоимости.

До записи событий и payloads заменяются известный настроенный API-ключ, значения известных секретных переменных окружения, Bearer-токены и значения чувствительных полей; HTTP headers исключаются. Настройки клиента и всё окружение целиком не сериализуются. Полные prompts, тексты задания, описания данных, исходный код и ответы всё равно могут содержать конфиденциальные данные: локальная трасса не является обезличенным отчётом. Очистка трассы не переписывает входные CSV, модели, snapshots кода и остальные артефакты запуска.

SQLite является источником истины: при повторном открытии sink JSONL полностью восстанавливается из committed-записей, затем дополняется с прежней последовательностью `seq`. Прерванный span может остаться без завершения — это свидетельство прерывания, а не успешного выполнения. Отчёт проверяет размер и SHA256 payloads; отсутствие или повреждение отмечается в `Trace integrity warnings`, не мешая чтению остальных событий. Сохранённые дедлайны запуска и кодирования не обновляются при resume. Для переноса работающего журнала нужна согласованная SQLite-копия с WAL; проще дождаться завершения и сохранить весь каталог запуска вместе с payloads.

Постановка подтверждается инструментом confirm_task внутри разведчика; отдельная CLI постановщика удалена. Запросы, SQL-инструменты, подтверждение и частичные отчёты входят в общую трассу запуска.
