# Исправление принадлежности к группам v4

> Текущий runtime v5 сохраняет это исправление; дополнительные изменения:
> [оценки времени и замены признаков](ADVISORY_COSTS_AND_REPLACEMENT_RU.md).

В полном v3 прогоне SearchGroupPlan сравнивал group IDs до того, как plan_ensemble
присваивал родителя. Отказ происходил после сохранения accepted plans; повтор брал те
же планы и падал снова. Это техническая ошибка связывания, не невалидный ML-рецепт.

Исправление:

- PlannerPlan содержит только агентские решения; внутренние membership поля исключены
  из output_schema и не принимаются как источник принадлежности даже в старом ответе.
- Контроллер передаёт containing parent в planning graph и связывает каждый вариант
  до технического/семантического review. Семейства используют контроллерскую metadata.
- SearchGroupPlan проецирует принадлежность на варианты. Сравнение независимых строк
  с отказом Variant belongs to a different search group удалено.
- Сохранённые approved/proposed планы получают ту же контроллерскую принадлежность
  перед cache comparison. Исторический lineage не становится текущей группой.
- Локальная ошибка одного ensemble recipe записывается с методом; остальные выбранные
  recipes продолжаются. Cancellation/global API/infrastructure exceptions передаются выше.

Новый runtime contract: 4. Запускать в новом каталоге. Исходные артефакты прогона
и ZIP v3 сохранены. Другие причины из ERROR_ANALYSIS_RU.md требуют отдельных изменений.

Проверки: tests/test_controller_groups.py воспроизводит реальные несовпадающие ID,
наличие независимого плана, pre-review binding, cache reuse, отказ среднего рецепта
с сохранением соседних и фактический SDK fit выбранных recipes с frozen DSL.
