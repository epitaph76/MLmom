# Контракт модели v2 и экономия токенов

Новые запуски используют runtime contract 2. Старые session.json нельзя продолжать
новым runtime: нужно начать новый запуск. Старые модели доступны для inference.
Исторические артефакты и замороженный ZIP cf471a… не изменены.

## Модель и фактическое обучение

HypothesisPlan отдельно задаёт target_transform, weight_policy, prediction_policy
и intervention. model_params сохраняет параметры backend. ModelSpec v2 объединяет
фактический экспорт, все политики, code_hash, preprocessing_hash и необязательный
feature_set_hash. Хеш конфигурации
считается по полному ModelSpec.

Число CPU-потоков (`n_jobs`, `nthread`, `num_threads`, `thread_count` и их
поддерживаемые варианты) относится к ресурсам исполнения и не входит в
`ModelSpec.backend_params` или хеш модели. Worker подставляет свою текущую
CPU-квоту в существующие настройки потоков перед созданием кандидата: параллельное
сравнение может использовать по 2 CPU, одиночный полный refit — все доступные 6.
Параметры обучения, seed, device, политики и признаки остаются зафиксированными.
Полный экспорт сохраняет фактически использованные настройки, а
`execution-report.json.execution_resources` отдельно показывает выделенные CPU,
заявленные/экспортированные потоки и проверенные параметры каждого компонента.
Выход за CPU-квоту, неограниченное `-1` и попытка скрыть превышение изменением
post-fit атрибутов отклоняются. CPU/RAM admission и изоляция workers сохраняются.
Проверки: `tests/test_execution_resources.py` выполняет реальные refit на
LightGBM, XGBoost и CatBoost с 2 и 6 CPU и проверяет одинаковый хеш модели.

DSL-наборы, отдельная область feature-CV, фиксированный baseline и перенос признаков
через HPO/refit описаны в [FEATURE_AGENT_RU.md](FEATURE_AGENT_RU.md). Существующие
session с runtime contract 2 без feature_search_enabled продолжаются с отключённой
feature-веткой; сам контракт модели остаётся v2.

SDK выполняет identity/log1p с обратным преобразованием, clipping/nonfinite policy
и fold-local balanced/sqrt_balanced/tail_aware weights. Они умножаются на заданные
веса строк. Кодер передаёт context.sample_weight без повторного вычисления политики.
Вложенные компоненты не применяют её дважды. Параметры преобразований, включая
обученные медианы, сохраняются для переносимого inference.

Пользовательские HPO-поля имеют маршрут policy_params.<policy>.<field>; они не
попадают в backend params. Выбранный ModelSpec используется при incumbent и final refit.

Worker устанавливает перехват backend fit до загрузки кандидата. Снимок параметров,
хеши target/weights, число строк, стадия и версии кода хранятся вне FitContext кандидата.
Для native AutoML фиксируется и граница его fit: внутренняя перестановка строк
отличается от скрытого преобразования пользовательским кодом. Изменение post-fit
атрибута не меняет запись. Отсутствующее доказательство или неверные веса/target
дают диагностический отказ. Как и прежний SDK, это не песочница для вредоносного Python.

## Планирование и проверка

validation_protocol проверяется по нормализованным управляющим полям. Описательные
дополнения сохраняются в validation_metadata; расхождения сообщаются с именем поля.

Автоматический HPO получает отдельную intervention и родительский эксперимент.
Один вариант исполняется как одиночная конфигурация. Ablation сохраняет остальную
конфигурацию и проверяет число изменённых групп операций/политик.

Машина проверяет совместимость до semantic validator. Блокирующее замечание
требует поля плана и проверяемого основания; неподтверждённая несовместимость
становится предупреждением. Для LightGBM native categorical есть локальный
known/unseen/missing probe. Reviewer получает все fold results, score_std, OOF,
ModelSpec, intervention и сопоставимый контроль, раздельно от smoke. Исходники
доступны через read_evidence. Reviewer не отменяет machine execution gate.

## Контекст, ремонт и соединение

Передаются канонический briefing, все critical facts, до 24 выбранных находок,
полный индекс observation IDs и ссылки на подробности. previous_brief содержит
компактное прошлое состояние. Полное условие доступно через read_task.
Размер JSON не объявляется числом токенов.

Совместимая предобработка переиспользуется. При изменении только параметров
переиспользуется код модели. Существующие файлы ремонтируются через CodePatch:
SHA256 фактических байтов, однозначные блоки, контроль владельца и запрет замены
всего файла. write_file/CodeBundle отсутствуют в ремонте; первичное создание
сохраняет CodeBundle. Workspace записывает исходники с LF.

Thinking выключен только для context_agent/training_agent. Остальные роли работают
в обычном режиме. Числовых лимитов reasoning/output tokens нет. Неподдерживаемый
параметр выключается один раз для подключения с записью в trace. Usage reasoning
не прибавляется повторно к completion; cached не прибавляется к prompt.

Общий circuit breaker после трёх connection/timeout/500/502/503/504 сбоев ждёт
30 секунд, затем допускает один ожидающий рабочий запрос без внутренних повторов.
Успех возобновляет работу, сетевой отказ повторяет паузу. Ошибки JSON не считаются
сетевыми. Остановка по API-бюджету сохранена. Watchdog не изменялся.

## LightGBM: выполненные обновления и сохранённые деревья

Для LightGBM `current_iteration()` показывает число сохранённых раундов модели,
которое может быть меньше числа выполненных `Booster.update()`: обновление без
допустимого split не добавляет деревья. Например, на multiclass smoke из 60 строк
500 обновлений дали 499 сохранённых раундов, а 100 — 99.

Runtime отдельно фиксирует реальные вызовы `Booster.update()`, начальный и конечный
счётчики, добавленные раунды и подтверждённые пустые обновления. Причина
`iteration_limit_with_noop_updates` допустима только при выполнении всего лимита,
совпадении фактического booster и согласованной последовательности счётчиков.
Экспорт сохраняет заданный фиксированный лимит. Реально укороченное обучение,
превышение лимита и подмена атрибутов после fit по-прежнему отклоняются.

`categorical_feature`, переданный через `fit()`, включается в доверенный снимок
аргументов на входе backend. Он проверяется наравне с параметрами конструктора;
другой список категориальных колонок не может пройти проверку.

Воспроизведение и исправленные smoke-отчёты: `artifacts/lightgbm-fix-20261024/`.
Регрессии: `tests/test_lightgbm_fit_evidence.py`.
