# Генерация кандидатов вместо фиксированных адаптеров

С 22.10.2026 каждый новый кандидат, включая быстрый baseline, проходит LLM-кодер с полной генерацией подготовки данных, вызовов выбранной библиотеки, predict и сохранения. Режим `adapter_only` удалён. Поле execution_mode сохранено в контракте с единственным значением custom; старое значение не принимается.

## Скиллы и примеры

Основные инструкции SKILL.md получают планировщик, валидатор и кодер. Только кодеру дополнительно передаются REFERENCE.md выбранной библиотеки, preprocessing и SDK. Примеры адаптированы из прежних адаптеров: sklearn содержит полный пример, остальные библиотеки — фрагменты API и правила интеграции. Это контекст для генерации, а не вызываемая реализация модели. Подключение других backend-примеров автоматически не происходит.

SHA256 скилла включает фактически переданный текст и примеры. Общий лимит обычного контекста — 24000 символов, кодера с примерами — 48000. Все выбранные тексты сохраняются в трассе и входят в версии кандидата. Кодер может использовать сторонние установленные библиотеки и SDK; импорт mlmom.adapters или наследование LibraryCandidate отклоняется AST-проверкой.

## План и обучение

План явно задаёт preprocessing с названиями колонок, модель и параметры. Фразы «год категориальный», «оставить NaN» и «clip прогноз» должны стать кодом кандидата. LLM-валидатор проверяет выполнимость плана; исключения при временной недоступности валидатора для бывших фиксированных обёрток удалены.

Baseline остаётся дешёвым: strategy=single, max_trials=1, без ансамблей, native AutoML или тяжёлых сетей. Он может иметь search_space для последующего HPO, но первая тренировка поиска не выполняет. После корректного CSV тот же исходник используется в Optuna. Пространство параметров теперь объявляет планировщик; инфраструктура не угадывает параметры неизвестного кода. Каждый объявленный параметр должен использоваться кандидатом. История и дедлайн study, внешний split, сравнение переобученного чемпиона и сохранение предыдущего CSV продолжают контролироваться инфраструктурой.

## Проверки и надёжность

Синтаксис/импорты, smoke fit/predict/save/load, переносимость состояния, изоляция данных и CPU/RAM/deadline остаются обязательными. Исправление сгенерированного кода разрешено и после runtime failure baseline, в исходном окне кодирования. Повтор не считается новым циклом. Ошибка новой гипотезы не уничтожает рабочий CSV.

Прежний mlmom/adapters.py остаётся внутренним кодом проб библиотек и загрузки исторических артефактов. Новые кандидатные реализации через него не исполняются. Исторические запуски и модели не переписываются. Для перехода следует создавать новый run-dir: планы и проверенные обёртки старого формата нельзя безопасно считать результатами новой политики.

Smoke подтверждает работоспособность, но не доказывает выполнение любой смысловой гипотезы. Генерация полного кода устраняет принудительный запрет изменений; соответствие конкретных гипотез всё ещё зависит от плана, реализации и проверок. Новые платные LLM-прогоны не являются частью offline-тестов.
