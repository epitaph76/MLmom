# Внутренняя валидация и внешнее сравнение

Внешнее разбиение меняется каждый цикл. Чемпион переобучается на текущем train
с сохранёнными параметрами и сравнивается с кандидатами на текущем holdout.
Оценки прошлых циклов служат историей, не порогом продвижения.

`TaskDefinition.validation_strategy` задаёт внутреннюю проверку: holdout, kfold,
stratified_kfold или group_kfold. `validation_folds` по умолчанию 5, минимум 2.
Для holdout используется `inner_fraction`; при наличии групп — GroupShuffleSplit.
Нехватка групп/примеров класса не уменьшает число фолдов и не заменяет стратегию.
StratifiedKFold применяется к одному классификационному target; расширение
multilabel CV в этот объём не входит, существующий multilabel holdout сохраняется.

Один trial проверяет одну конфигурацию во всех фолдах. Каждый fit создаёт свежие
модель и предобработку. Обучаемые преобразования, включая OOF target encoding,
используют только train своего фолда. В обычном CV validation_X/y не передаются
в fit: ранняя остановка по оценочному фолду отключена, параметры фиксированы.

Критерий выбора — арифметическое среднее score фолдов. `score_std` — стандартное
отклонение с ddof=0, отсутствует для holdout. `oof_score` считается отдельно по
объединённым предсказаниям. Индексы и seed находятся в validation-protocol.json;
исходные позиции и outer_split_id связывают его с внешним разбиением.

Worker сохраняет trials.json после фолдов и selection.json после полного trial.
Только законченный refit на всём разрешённом train создаёт completed progress.json
с full_refit=true. stop завершает поиск и сохраняет обязательность refit.
Исходные дедлайны worker/HPO сохраняются; resume не расширяет их.

Native AutoML допускается только по `validation_strategies` каталога. Проверен
FLAML holdout с ensemble=False и frozen refit без поиска. AutoGluon и LightAutoML
не имеют подтверждённого generated-пути без ансамблей с полным refit и пока
отклоняются. Старые адаптерные пробы не подтверждают этот путь.

Объединение кандидатов, blending/stacking запрещены. ExtraTrees и другие обычные
estimator разрешены. SDK, контракт строк и формат сохранённых моделей не менялись.


## Уточнения контрактов после ревью 22 октября 2026

По умолчанию timeouts_enabled=false; временные окна действуют при явном включении.
Ограниченные diagnostic/replay entrypoints включают их явно. Старые session без флага
восстанавливаются с прежней политикой true; явно менять её при resume нельзя.
Прогнозы worker передаются через Parquet с сохранением типов меток.
Multilabel log_loss — средняя binary cross entropy по меткам с весами строк.
Multilabel stratified_kfold отклоняется при подтверждении; используйте holdout или group_kfold.
Ансамбли разрешены, но native AutoML-компоненты пока отклоняются до проверки frozen refit.
Для stacking с отдельной предобработкой обязателен fit_stack(X,y,context,create_preprocessor):
он получает исходный X. Каждая база оборачивается PreparedCandidate с собственной
предобработкой внутри OOF-фолда и при полном refit. predict получает исходные признаки;
сохранение включает обёрнутые базы и метамодель. Прежний estimator-only fit остаётся
путём обычных кандидатов и blending. Это уточнение заменяет прежние запреты ансамблей
и утверждения об обязательности временных лимитов в этом документе.
