# Окружение worker: исправление 22.10.2026

Исправление относится к актуальной версии MLmom и её текущему submission ZIP.

## Подтверждённые факты

Исследованный архив из Downloads имеет SHA256
4e6e00d45202f8320777bbef20a6a97dd48322ce522a5e0575ab5757416100fe.
В нём только solution.py, requirements.txt и mlmom_bundle.py. Зависимости
побайтово совпадают с предоставленным списком. Восстановление собственных
модулей в подпапке во время исполнения разрешено правилами платформы.

Launcher использовал sys.executable, а не зашитый системный Python или локальный
путь разработчика. Однако PYTHONPATH заменялся только корнем нашего runtime,
а HOME — каталогом worker. Это могло скрыть библиотеки, видимые контроллеру
через внешний PYTHONPATH, пользовательский site или изменённый sys.path.
Удаление VIRTUAL_ENV само по себе не доказывает выход из venv.

В локальном Python 3.12 воспроизведены два случая: обычная venv запускает worker
успешно; пустая venv с доступом к уже установленным пакетам через PYTHONPATH
позволяет запустить контроллер, но исходный worker падает с
ModuleNotFoundError: No module named 'pydantic'. Ошибка возникает при импорте
mlmom.__init__, ещё до worker.main и его обработчика исключений.

Это подтверждённый дефект переносимости. Причина конкретного ночного запуска
остаётся неподтверждённой: организаторы предоставили описание, без traceback,
команды установки пакетов или фактических sys.executable/sys.prefix. Контейнер
организаторов локально недоступен; проверки выполнены на Windows/Python 3.12.

## Исправление актуальной версии

- Worker использует исходный sys.executable без resolve, чтобы не обходить
  venv через разрешение симлинка на базовый интерпретатор.
- PYTHONPATH включает абсолютные пути из эффективного sys.path контроллера
  и корень нашего runtime. Лимиты CPU/RAM и фильтрация секретных переменных
  окружения сохранены. Новые пакеты и установка зависимостей не добавлены.
- Каждый запуск пишет runtime.json: executable, version, prefix, base_prefix,
  sys.path и команду запуска контроллера; worker добавляет фактические значения.
  При падении ещё до main остаются снимок launcher и stderr.log.
- Перед графом задач и любым LLM-запросом запускается настоящий runtime_check
  worker под Scheduler, до 30 секунд внутри общего research budget. Он импортирует
  pydantic, psutil, numpy, pandas, cloudpickle, sklearn, polars и pyarrow.
- Проверяются совпадение executable/prefix/base_prefix и версий этих пакетов
  между контроллером и worker. При ошибке запуск получает worker_runtime_error
  с конкретной причиной и прекращается до LLM и экспериментов. Ошибка сохраняется
  в summary.json и failure_causes.
- При resume проверка выполняется заново. Если бюджет истёк и корректный
  submission уже сохранён, он сохраняется без новой проверки/расходования резерва.

## Проверки

Регрессионный тест создаёт пустую venv без pip и передаёт существующие пакеты
только путями контроллера. В ней должны работать runtime_check и реальное
обучение/predict/save/load worker. Отдельно имитируются отсутствующая библиотека,
другая venv и несовпадающие версии: ни один такой случай не вызывает LLM.

Проверяются два цикла регрессии и классификации, resume, Scheduler, отсутствие
API-ключей в worker и автономный ZIP с копированием только трёх корневых файлов.
Платных LLM-вызовов и отправки на платформу эти проверки не выполняют.

Машинные результаты текущей сборки: submission/validation.json. Локальные
протоколы и воспроизведение: artifacts/organizer-worker-investigation/.

[Правила Python 3.12 для site-packages](https://docs.python.org/3.12/library/site.html).
