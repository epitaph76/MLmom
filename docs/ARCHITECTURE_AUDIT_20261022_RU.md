# Архитектурный итог двух реальных прогонов — 22.10.2026

Сводка DeepSeek и Qwen без вопросов API, шлюзов и бюджета. Оба запуска использовали
одинаковый runtime ZIP SHA256
`d00c03291f75bfe0c75c002480c60da5379a169fbab0da91bed895ec815e1f2c`.
Ниже перечислены обнаруженные проблемы, которые **ещё не исправлены** в этой сборке.
Уже внесённые исправления описаны отдельно в [REVIEW_FIXES_20261022.md](REVIEW_FIXES_20261022.md).

## Подтверждённые проблемы

1. **Потеря результатов разведки между ролями.** `save_observation` требует точных
   чисел, но семантика `rows` для агрегированного SQL не объяснена. Общая ошибка не
   указывает неверное поле. Модели затем используют несохранённые IDs, а обработка
   финального ответа отбрасывает весь набор предложений. На Qwen осталось 25
   `csv_result`, но ни одного сохранённого наблюдения; детерминированный профиль
   доступен следующей роли, отдельные выводы разведки — нет. Аналогичный класс
   отказа наблюдался на DeepSeek.

2. **Неполный export нарушает воспроизводимость refit.** Кандидат может вернуть из
   `export_model_params` только количество деревьев, тогда как worker использует
   результат как полную замену конфигурации. Последующее создание модели теряет
   learning rate, глубину, параметры ансамбля и выбранные HPO значения. SDK и
   примеры недостаточно явно требуют полный воспроизводимый набор параметров.
   На DeepSeek дефект подтверждён у двух новых кандидатов; они не стали Champion.

3. **Нет достаточной проверки соответствия исполнения плану.** Smoke проверяет
   предсказания и сохранение модели, но не фактическое число итераций. В реальном
   DeepSeek blend CatBoost имел 1 дерево вместо 800 из-за обратного условия callback.
   Result validator признал реализацию соответствующей гипотезе. Нужны фактические
   iterations, effective params и stopping reason до научного анализа результата.

4. **Неоднозначные метрики распространяют ошибочные выводы.** Slice `mean_error`
   содержит MAE, но трактуется как направленное смещение. Внутренняя CV также
   сравнивается с историческим внешним holdout. Нужны отдельные `mae` и
   `mean_residual` с определениями, а также `score_kind` и идентификатор split.

5. **Текущая конфигурация смешана с устаревшим описанием.** Следующая роль получает
   правильные параметры Champion и одновременно старый текст гипотезы с другими
   параметрами и score. Модель выбирает устаревшие значения. Фактическая
   конфигурация должна иметь один явный авторитетный источник.

6. **Skills и диагностика не покрывают ограничения инструментов.** Не описаны
   допустимые `metric_options`, семантика `rows`, полный export/recreate и основные
   ограничения Polars SQL. Длинные traceback и общие ошибки вызывают лишние ремонты.
   Контроль повторных неуспешных `save_observation` слабее контроля readonly tools.
   При этом выдуманные IDs и смешивание источников нарушают уже переданные
   инструкции: одного расширения skills для устранения проблемы недостаточно.

7. **AST-проверка даёт ложный отказ.** Стандартный
   `from __future__ import annotations` отклоняется whitelist импортов, что вызвало
   ненужную регенерацию корректного по этому признаку файла.

8. **Текст протокола не гарантирует его исполнения.** План обещает duplicate-aware
   разбиение, но подтверждённый runner выполняет обычный `kfold` без групп.
   Предупреждение валидатора оставляет расхождение нерешённым.

## Приоритет исправлений

1. Уточнить сохранение наблюдений, давать ошибки по полям, передавать разрешённые
   IDs и восстанавливать проверенные части результата без принятия выдуманных фактов.
2. Обеспечить полный roundtrip export/recreate конфигурации, включая ансамбли и HPO.
3. Проверять фактическое исполнение эксперимента до оценки полезности гипотезы.
4. Сделать определения метрик, уровни оценки и текущее состояние Champion однозначными.
5. Уточнить skills, SQL-примеры и протоколы валидации; устранить ложные отказы AST.

## Границы доказательств

Потеря результатов разведки подтверждена на обеих моделях. Дефекты обучения,
экспорта, ансамбля и анализа метрик подтверждены на DeepSeek; Qwen до этих стадий
не дошла. Эти результаты не позволяют объяснять проблемы размером модели или
сравнивать качество обученных моделей.
