# Контроль workers и инфраструктурные ошибки

Watchdog выполняет три проверки: родительский контроллер ещё жив, RSS дерева
worker не превышает выделенную память, временное окно не исчерпано. Проверка
времени выполняется только при `timeouts_enabled=true`. Контроль памяти и
оставшихся процессов работает и без таймаутов, включая запуск в Docker.

## Идентичность процесса

В Linux epoch timestamp из `psutil.Process.create_time()` зависит от преобразования
через boot time. При расхождении этого значения между долгоживущим контроллером
и свежим worker точное равенство может ложно сообщить о смерти родителя.

Новые запросы содержат `parent_identity`: PID, starttime в kernel ticks из поля 22
`/proc/<pid>/stat` и boot ID, если он доступен. Они не зависят от перевода в календарное
время. Повторное использование PID и смена boot ID не проходят проверку.
В Windows используется нативное время создания процесса. Zombie считается завершённым.
Отказ доступа означает «не удалось проверить»: он не выдаётся за смерть родителя
и не разрешает уничтожать процесс при уборке.
Для старого worker request без identity проверяется связь с непосредственным родителем.

Та же идентичность применяется к сохранённым worker records при resume и к уборке
дочерних процессов. Старые checkpoint records с `created` читаются консервативно;
несовпадение времени не разрешает уничтожать посторонний процесс.

## Поведение при отказе

`parent_exit` и `controller_closed` — инфраструктурные причины.
Scheduler поднимает `WorkerInfrastructureError`, передавая исходный результат и
каталог доказательств. Ошибка проходит через tools и роли без преобразования
в подсказку для LLM или отрицательное доказательство качества модели/признаков.

Контроллер останавливает прогон с `status=failed`,
`stop_reason=worker_infrastructure_error`, сохраняет
`worker-infrastructure-failure.json`, событие в SQLite и summary.
Другие активные workers освобождаются при закрытии scheduler. Уже созданный CSV
и артефакты сохраняются, но их наличие не превращает инфраструктурный отказ
в успешное завершение pipeline. Финальный refit автоматически не запускается.

Ошибки модели, execution fidelity и превышение её памяти остаются отдельными
причинами с прежними правилами проверки/ремонта. Защитные лимиты не отключаются.

## Проверки

`tests/test_worker_supervision.py` проверяет расхождение psutil на одну секунду
в настоящем Linux worker, reuse PID/boot ID, сохранение memory guard при отключённых
таймаутах, гибель контроллера с уборкой worker и его дочернего процесса, прекращение
генерации после инфраструктурной ошибки, а также smoke, async training, inference,
publication, diagnostics и final refit. Все LLM в этих тестах локальные fakes;
Docker-проверки запускаются без сети. Логи проверки исправления сохраняются
в `artifacts/watchdog-fix-20261023/`; исторический исследованный runtime не меняется.
