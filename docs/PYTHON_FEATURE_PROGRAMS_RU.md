# Исполняемые Python-признаки — runtime v6

Feature Agent может вернуть собственный Python-модуль в FeatureProposal.programs.
DSL в features остаётся сокращённой формой для простых операций. Он больше не
ограничивает доступные методы или число колонок. Жёсткие лимиты 8/16 признаков
сняты; фактические CPU/RAM, дедлайны и бюджет экспериментальных конфигураций остаются.

Программа имеет name/source/config. Source определяет create_features(config),
объект реализует fit_transform(X,y,context) и transform(X). Вход — исходные разрешённые
колонки; выход — дополнительные DataFrame, NumPy или scipy sparse колонки. Каждый
fold создаёт новое состояние программы, transform получает только X. Программа и её
обученное состояние сохраняются с моделью, включая перенос в ансамбли и full-train refit.

Разрешены обучаемые представления, target encoding, составные ключи, сглаженные
таргетные статистики и история. Изоляцию внешних меток обеспечивает исполнение folds;
при построении обучающих target-derived колонок автор использует cross-fitting либо
исключение собственной метки/года. Программа не должна переобучаться на prediction batch.
Нет blanket-запрета target-dependent features или требования официального entity ID.
Предполагаемая сущность проверяется как эксперимент по фактам и измерениям.

Программы исполняются внутри обычного ML worker с установленными зависимостями.
Переданный feature context очищен от validation_X/y/groups/weights. Ресурсы и остановка
контролируются тем же supervisor; новые provenance/audit/novelty gates не добавлены.
Ошибки Python сохраняют имя программы и traceback и возвращаются агенту.

add/remove/replace действуют на имена DSL-признаков и Python-программ. Замена
сравнивает один итоговый набор; обе стороны сохраняются в pending/evidence. Хеш
программы включает исходник и config, поэтому смена кода образует новую конфигурацию.
Хеш старого DSL-набора сохранён; старые inference artifacts остаются загружаемыми.

Runtime contract=6: новые прогоны — в новых каталогах, старые сессии не переносить.
Контрольная модель/гиперпараметры/folds фиксируются при измерении признаков. Программа
может обучать представление, сохраняя контрольную модель и её параметры.
Для отдельной гибридной логики предсказания остаётся обычный custom candidate.

## Проверка

tests/test_feature_programs.py проверяет обучаемые target statistics с исключением
собственной метки, отсутствие validation labels, реальный worker CV, сохранение модели,
учёт программ в identity, атомарную замену и повтор feature session без лишнего fit.

scripts/probe_feature_programs.py отдельно вызывает только живой Feature Agent на
сохранённых контекстах regression/multiclass. Ему передаётся текущий контракт, библиотеки,
замороженная модель и история признаков; historical_blending.py и готовые идеи не
подставляются. Запрашивается конкретный Python-эксперимент. Контроль и предложение
измеряются на одном subset outer train и одинаковых внутренних folds, без HPO.
Это exploratory-проверка исполнимости/идей, не внешняя оценка качества полного решения.

Две живые пробы 25.10.2026 сохранены в
artifacts/feature-programs-v6-20261025-100146Z/REPORT_RU.md вместе с входами,
предложениями, исполняемым кодом, CV и trace. Предложения исполнились с первой
попытки. Это не подтверждение качества на полном датасете или отсутствия всех
методологических ошибок: например, у регрессионного предложения отдельно отмечены
общий prior и различия train/inference. Текущий prompt явно распространяет правило
cross-fitting/исключения своей метки также на priors/fallbacks.
