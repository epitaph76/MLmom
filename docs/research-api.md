# Research API v1 — передача тиммейту

Нормативный контракт — `contracts/research.openapi.json` (OpenAPI 3.1, версия `1.0.0`); примеры лежат рядом в `examples`. Реализация сервиса и язык свободны; изменение этого интерфейса согласуется с клиентом и сопровождается обновлением контракта.

## Маршруты

| Метод | Путь | Успешный ответ |
|---|---|---|
| GET | `/health` | 200: `status: ok`, `contract_version`, `mock` |
| POST | `/v1/research/jobs` | 202: текущий `ResearchJob` |
| GET | `/v1/research/jobs/{job_id}` | 200: текущий `ResearchJob` |
| POST | `/v1/research/jobs/{job_id}/cancel` | 200: текущий `ResearchJob` после запроса отмены |

Создание сразу возвращает ID; карточки приходят в последующем GET. Транспорт использует UTF-8 JSON и `Content-Type: application/json`.

## Запрос

| Поле | Тип | Требование |
|---|---|---|
| `request_id` | string | Обязательно, 1–128 символов; идентификатор идемпотентности |
| `task` | string | Обязательно, 1–20000 символов; текст задачи |
| `task_type`, `metric` | string или null | Необязательно; пока без фиксированного перечня ML-задач |
| `dataset_summary` | object или null | Необязательные метаданные датасета |
| `constraints` | object или null | Необязательные ограничения |

Сырые данные и пути к локальным файлам не нужны. Повтор с тем же `request_id` и эквивалентным JSON-телом возвращает существующее задание; значения по умолчанию и явный null эквивалентны, порядок ключей не важен; другое тело даёт 409 `REQUEST_ID_CONFLICT`.

## Задание и результат

| Поле | Содержание |
|---|---|
| `job_id`, `request_id` | ID задания и исходного запроса |
| `status` | `queued`, `running`, `succeeded`, `failed`, `cancelled` |
| `result` | Только при `succeeded`: `cards` и `hypotheses`; иначе null |
| `error` | Только при `failed`: стандартная ошибка; иначе null |
| `mock` | true для синтетической реализации; реальный сервис возвращает false |

Карточка: `id`, `url` (HTTP/HTTPS), `title`, `source_type` (`web`, `github`, `paper`), `findings: string[]`, `limitations: string[]`. Гипотеза: `id`, `description`, `rationale`, `card_ids: string[]`, `proposed_experiment: object`; ссылки должны указывать на существующие карточки, ID внутри каждого списка уникальны.

Успешный поиск может вернуть два пустых списка. `proposed_experiment` содержит предложение, не исполняемый код и не подтверждённые метрики; текущая версия не задаёт формат будущего ML-рецепта.

## Состояния и ошибки

Обычный путь: `queued → running → succeeded | failed`; активное задание может перейти в `cancelled`. Терминальные состояния неизменны: повторная отмена не меняет их и сохраняет готовый результат.

Все заявленные HTTP-ошибки содержат `code`, `message`, `retryable`, `request_id` (null, если неизвестен), `mock`. 404 означает `JOB_NOT_FOUND`, 409 — конфликт `request_id`, 422 — `VALIDATION_ERROR`; job-level ошибка поиска приходит в `error` при HTTP 200 и `status: failed`.

Отмена должна быть быстрой и идемпотентной; завершённая до отмены работа сохраняет результат. Ошибка соединения не означает отмену: клиент может повторить GET, а после неоднозначного POST — повторить создание с тем же `request_id`.

## Клиент и mock

`ResearchClient` экспортирует `create`, `get`, `cancel`, `waitForJob`. GET повторяется ограниченно при сетевых сбоях, таймауте и 429/5xx с `retryable: true`; POST автоматически не повторяется.

`waitForJob` поддерживает `AbortSignal` и `cancelOnAbort`; Pi включает отмену для явно остановленного ожидания. Таймаут ожидания сохраняет задание; неудачная отправка отмены сообщает, что её результат неизвестен.

Только mock понимает заголовок `X-Mock-Scenario: success | empty | failed`; по умолчанию `success`. Все его ответы помечены `mock: true`; заголовок не нужен реальному сервису и не входит в смысл пользовательского запроса.

Для подключения реализации задайте `RESEARCH_MODE=external` и `RESEARCH_URL`, затем перезапустите `npm start`. Рекомендуется сначала прогнать HTTP-сценарии из `tests/test_research.py` против реализации; mock хранит задания только до перезапуска, реальному сервису потребуется собственная политика хранения и восстановления заданий.
