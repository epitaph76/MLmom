# Агентский пайплайн: runtime v3

Начальные модели и их priority выбирают Hypothesis Generator и Planner для подтверждённой
задачи. Boosting не обязателен; выбранная семья может содержать несколько реализаций.
Сначала одобряется контроль. Планирование альтернатив и подготовка независимых кандидатов
идут параллельно с ним, не задерживая выпуск первого полноценного результата.

Feature Engineer вызывается сразу после Context agent на профиле только outer train.
Первое предложение сохраняется до подготовки модели. После готовности контроля признаки
измеряются на его замороженных параметрах и одинаковых внутренних folds до длительного HPO.
Первоначальная модель остаётся контролем; предложение и измеренное улучшение различаются.

Первый успешный контроль проходит submission_refit на всём train. Публичный CSV содержит
только полноценный результат при включённом cycle_full_refit. Следующие циклы заменяют его
атомарно после успешного refit; ошибка нового fit сохраняет прежний файл и его источник.
Оценочные модели и submission_refit не участвуют в одном сравнении.

## Поиск и бюджеты

| Поле | Значение по умолчанию | Назначение |
|---|---|---|
| timeouts_enabled | false | Нет общего дедлайна; агент получает remaining_seconds=null |
| preparation_workers | 3 | Ограниченный пул независимой подготовки с отдельными контекстами |
| hpo_initial_trials | 15 | Начальный бюджет, если Planner не указал иной |
| HypothesisPlan.hpo_trial_budget | null | Начальный бюджет последующего HPO фиксированного baseline |
| hpo_max_trials | null | Явный пользовательский максимум; без него агент может продлевать study |
| hpo_batch_size | 5 | Размер пакета новых обучений |
| hpo_startup_trials | 3 | Стартовые наблюдения TPE |
| TrainingDecision.additional_trials | 0 | Продление неизменённой study вместе с continue |
| runtime_repairs | null | Нет общего счётчика ремонтов; явный пользовательский максимум поддержан |

Числа trials выбирает Optuna; next_params больше не исполняется. Уже измеренный baseline
можно однократно импортировать как completed trial с исходными selection-артефактами, если
совпадают код, данные, признаки, фиксированные настройки и протокол. Импорт не расходует
новые обучения. Несовпадение означает обычный поиск без импорта, а не запрет эксперимента.
Источник может быть измеренным участником семьи до внешнего holdout. Потоки CPU не являются
гиперпараметрами модели; добавленные экспортом служебные значения не подменяют исходное задание.
Порог прироста 0,5% предлагает завершение поиска; Training agent может обоснованно продолжить.
При resume не повторяются импорт, применённые продления и завершённые решения checkpoints.

## Ансамбли и восстановление

Ensemble agent явно выбирает methods, oof_folds и weight_trials. Каждый выбранный рецепт
получает собственный план и рассмотрение. Python сохраняет исправления Planner и не
разворачивает mean в необъявленный поиск весов/stacking. Источники компонентов и их DSL
признаки сохраняются. execution_contract формируется из текущего SDK и схемы FeatureSpec;
историческая проза не переопределяет действующее feature_set.

Ошибки возвращаются ответственному агенту с конкретной причиной. Изменённый исходник
можно ремонтировать дальше; повтор неизменённого кода и конфигурации с той же ошибкой
откладывается для нового подхода. Одинаковый неудачный SQL-запрос возвращает сохранённую
ошибку без повторного worker. Дополнительной проверки «доказательства новизны» нет.
Plan validator сохраняет право отказа; result validator остаётся рекомендательным.

## Остановка и совместимость

Остановка немедленно отменяет ожидающие задачи, закрывает активные процессы и блокирует
применение запоздавших ответов ролей. Summary сохраняет interrupted/external_stop и отдельное
result_available; незаконченные задания отмечаются interrupted. Готовый CSV сохраняется.
Учёт незавершённых Optuna trials касается только активных studies, после сохранения summary.

Runtime v3 требует нового run-каталога. Старые исходные артефакты и отчёты не переписываются;
сохранённые модели старых версий остаются доступны для inference.
