# Diversity Evidence для ensemble_agent

Карточка ensemble_agent обновлена с 1.0.4 до 1.1.0. Агент получает фактические
измерения через compare_oof_components(experiment_ids), а выбранная композиция —
сохранённый структурированный отчёт. Его получают Planner и plan validator.
Старые инструкции по frozen models, независимым рецептам и ресурсам сохраняются.
Связанные карточки planner 1.6.0 и validation 1.3.0 описывают ту же область доказательств
и неизвестные величины без дополнительных причин для автоматического отказа.

## Какие утверждения поддержаны

| Поле | Измерение и граница вывода |
|---|---|
| pairs[].error_correlation | Взвешенная Pearson-корреляция остатков по каждому regression output либо индикаторов ошибки классификации. Постоянный вектор → null с причиной |
| pairs[].loss_correlation | Корреляция row MAE; для вероятностей — Brier loss, для labels — ошибки классификации. Это диагностические потери, не замена primary metric |
| pairs[].error_overlap | Число ошибок каждой модели, intersection/union, взвешенные доли и Jaccard. В регрессии событие: положительная row MAE ≥ собственного невзвешенного 80-го процентиля, включая равенство; в классификации — неправильный класс, для multilabel — хотя бы одна ошибка |
| incremental_benefit | Равновесное среднее без подбора весов: primary metric с действующими options/weights, одинаковыми фолдами и исходной шкалой. improvement_over_best > 0 означает улучшение с учётом minimize/maximize |
| full_refit_cost | Измеренные fit durations компонентов с числом строк и CPU/RAM; их историческая сумма — оценка, полная задержка ансамбля неизвестна. Дополнительные OOF-fit и meta/weight search указаны отдельно |

Для тройки leave_one_component_out также сравнивает полное среднее с каждой оставшейся
парой: improvement_from_adding_component > 0 означает пользу добавления именно этого
компонента. Успешная отдельная пара не подтверждает автоматически полезность третьего.

mean_fold_score не смешивается с pooled_oof_score. Это существенное различие:
оценка по собранным CV-предсказаниям может отличаться от среднего по фолдам,
в том числе для недекомпозируемых метрик. См. [scikit-learn cross_val_predict 1.5](https://scikit-learn.org/1.5/modules/generated/sklearn.model_selection.cross_val_predict.html).

Статусы отчёта: unverified_hypothesis, measured_diversity, historical_gain_observed,
historical_gain_not_observed. Вложенное измерение может иметь unavailable с причиной.
Даже historical_gain_observed подтверждает только конкретное диагностическое среднее
на исторических inner OOF. Компоненты могли быть выбраны по этим фолдам во время HPO,
а композиция — после нескольких сравнений. Это не независимая оценка обобщения и не
результат weighted/stack. Для таких рецептов SDK заново создаёт training-only OOF и
проверяет обученный ансамбль на отдельной оценочной части. Разделение обучения
meta-model на OOF и финального fit компонентов описано также в
[scikit-learn StackingRegressor 1.5](https://scikit-learn.org/1.5/modules/generated/sklearn.ensemble.StackingRegressor.html).

## Доступ к данным и сохранение

Новый oof.json version=2 содержит исторические validation targets, metric/options,
class order, weights, original-scale predictions, source row indices и fold numbers.
Это метки внутренней валидации из тренировочной части прежнего завершённого цикла.
Существующие поля indices/source_indices/predictions сохранены. Worker не читает для
этого внешнюю проверочную часть. Инструмент работает только с артефактами supplied
component IDs; он не открывает train/test/current holdout и не выдаёт сырые метки агенту.

Для вычисления нужны один dataset, точный сохранённый protocol, одинаковые source rows,
fold membership, targets, weights, class order, metric/options и исходная шкала выхода.
Пересечения строк из разных протоколов недостаточно. При несовпадении отчёт описывает
ограничение; эксперимент может быть предложен как гипотеза. Это проверка применимости
диагностики, не admission/provenance gate. Лимит чтения — 16 MiB на исторический artifact;
более крупные результаты помечаются unavailable, а не блокируют обучение.

Старый OOF version=1 не содержит нужного контекста. Его нельзя восстановить уверенной
догадкой; он остаётся unverified_hypothesis. Сохранённые labels позволяют сопоставить
ошибки, но не восстанавливают вероятности для настоящего runtime blend. В этом случае
измеряется только доступное разнообразие, прирост остаётся unavailable.

Инструмент сохраняет агрегаты как ensemble_diversity:<key> в ExperimentStore. После
выбора двух или трёх компонентов контроллер вычисляет/сохраняет итог с рецептами и
передаёт его Planner, review и ensemble_planning. Вся тройка не получает статус
подтверждённого измерения на основании одной доступной пары. Числа от runtime отделены
от agent_notes.diversity_evidence — интерпретации агента, ссылок и неизвестных величин.

FitExecutionFacts дополнен необязательным duration_seconds. Worker измеряет отдельные
fit, включая preprocessing; HPO, сохранение и predict в эту длительность не входят.
Сумма исторических выбранных refit не объявляется текущей ensemble latency, а значения
при других размерах выборки/ресурсах не переносятся безоговорочно. Для mean/median
нужен один полный fit на компонент, для weighted/stack — ещё oof_folds fit на компонент
и обучение весов/meta-model. Нет нового порога допуска по предполагаемой стоимости.

Схема API v8 обратно совместима. Старые runs и артефакты не переписываются. Только
замена SKILL.md не добавит инструмент и OOF metadata в старый runtime; нужен согласованный
архив исполнителя. Новых платных LLM-запросов для этой проверки не выполнялось.

## Проверки

В tests/test_ensemble_evidence.py проверяются отрицательно коррелирующие остатки с
точным взвешенным RMSE, независимый oracle log_loss для строковых классов, intersection/
union ошибок, undefined correlation, отсутствие gain для labels, несовместимые протоколы,
ошибки row mapping, legacy/missing OOF, отрицательный результат blend, неполная тройка,
стоимость refit отдельно от HPO и фактическая доставка инструмента/отчёта ролям с resume.
Тест worker проверяет реальный artifact version=2 и durations. Итог запуска и область
регрессий записаны в [VALIDATION.md](../VALIDATION.md).

76 регрессионных + 40 проверок остальных задач/карточек + 9 финальных тестов Evidence
успешны (119 разных тестов). После уточнения карточек повторно прошли ещё 19 проверок
карточек/доставки/упаковки. Полный suite повторно не запускался.
Формат карточки, документация, упаковка и локальный граф проверены отдельно.
