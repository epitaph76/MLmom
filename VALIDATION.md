# Проверка реализации — 21 октября 2026

## Текущий ZIP: снятие лимита токенов

Клиент больше не передаёт ограничение выходных токенов ни при первом запросе, ни при повторах и HTTP fallback. Старые поля конфигурации принимаются для совместимости, но игнорируются; `ROUTERAI_MAX_TOKENS` не читается. На текущем ZIP прошли 16 проверок LLM-клиентов, трассировки и упаковки с mock transport. Лог: `artifacts/no-token-cap/tests.log`. Проверены совпадение встроенных исходников с рабочим деревом и отсутствие настроенных секретов. Реальный API после этой правки не запускался.

## Предыдущая полная проверка

**81 тест прошёл на исходниках предыдущего ZIP, до снятия лимита токенов, за 239,699 секунды.** Проверка выполнена в Windows с Python 3.12.10; LLM и HTTP transport замоканы, платный API не использовался. Контроллер и workers загружались из восстановленного bundle; тестовые fixtures оставались вне архива.

Проверены установленные реальные адаптеры: sklearn, CatBoost, LightGBM, XGBoost, FLAML и statsmodels. AutoGluon, LightAutoML и torch в этой локальной среде отсутствуют; их реальное обучение этим прогоном не подтверждено.

Архив содержит ровно `solution.py`, `requirements.txt` и `mlmom_bundle.py`. Размер, SHA256, хеш bundle, базовый commit и сведения об изменённом рабочем дереве записаны в [submission/validation.json](submission/validation.json). Встроенные runtime, profiles и skills сверяются с текущими исходниками; проверяется отсутствие настроенных API-ключей.

## Проверенное поведение

- Максимум две новые гипотезы за раунд; простой первый раунд; запрет скрытого native AutoML при `strategy=single`.
- Baseline проходит LLM-кодер и публикуется до планирования альтернативы. Отказ альтернативы не уничтожает готовый результат. Сложные планы требуют второго раунда, корректного submission и бюджета.
- Кодогенерация, исправления и smoke используют единое окно до 300 секунд. Сохраняются время обучения, предсказания и финальный резерв; repair/resume не обновляют дедлайн.
- Единый admission для всех worker-действий, CPU affinity, ограничения памяти/времени, сохранение результатов и освобождение ресурсов. Повреждённый worker JSON не мешает остановке других процессов.
- Полные API requests/responses, физические retries, HTTP fallback, tool calls, снимки skills, ошибки JSON/лимита токенов, корреляция событий, очистка секретов, восстановление JSONL и диагностика повреждённых payloads.
- Исправления target inference, специфических метрик, приоритета основной метрики, output filename, даты-признака и согласованного чтения CSV. Отдельно проверены исходные условия обеих организаторских задач.
- Resume сохраняет валидный план альтернативы и увеличенный резерв финального обучения.

Подробный лог: `artifacts/reliable-start-release/tests.log`; машинный итог: `artifacts/reliable-start-release/tests.json`.

Обе доступные задачи проходят отдельные запуски с mock LLM и реальным CatBoost: два раунда, переоценка incumbent, полное финальное обучение и проверка submission.

Короткий smoke использует 30 деревьев глубины 4: он проверяет исполнение и формат, а не превосходство над baseline. Отчёт и расположение трасс указаны в `submission/validation.json`.

## Пределы выводов

Последующие диагностические запуски через реальную Qwen завершились на обеих задачах с `no_successful_candidates`, без обучения и submission. Пики памяти были ниже 0,4 ГБ; основными наблюдаемыми сбоями стали кодогенерация, лимит токенов, timeout и HTTP 502. [Подробная диагностика](docs/REAL_API_DIAGNOSTICS.md) содержит условия, различия таймаутов и ссылки на трассы.

Организаторы подтвердили, что первая загрузка также не сформировала файлы предсказаний из-за `no_successful_candidates`, поэтому обе задачи получили 0. Её внутренние ошибки без старой трассы неизвестны. Трёхчасовой стресс-прогон и повторный платформенный скоринг не выполнялись. Исторические OOF-метрики baseline и результаты других holdout-разбиений напрямую не сравниваются.

Public и private оцениваются отдельно; каждый score — среднее по двум соответствующим задачам. Один процесс решения получает одну задачу и отдельный трёхчасовой лимит.
