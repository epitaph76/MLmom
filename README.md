# MLmom

## Назначение
MLmom решает табличные ML-задачи: анализирует условие, генерирует и проверяет кандидатов, проводит эксперименты и сохраняет `submission.csv`. Этапы 2–4 реализованы поверх первого этапа из ветки `DataAnalisys`; оркестрация использует LangGraph 0.6.7.

## Запуск на платформе
Платформа предоставляет Python 3.12, зависимости и переменные `OPENAI_API_KEY`/`OPENAI_BASE_URL`; `OPENAI_MODEL` необязателен и по умолчанию равен `qwen/qwen3.8-27b`. Пути данных разрешаются относительно `task.md`, итоговый файл записывается рядом с ним.

```bash
python solution.py task.md
```

## Локальный запуск
Установите зависимости заранее и сохраните ключ в игнорируемом `.env`; dev-профиль читает `OPENAI_*` и совместим со старыми `ROUTERAI_*`. Платформенный профиль читает подключение только из окружения.

```bash
python -m pip install -e .
python solution.py /path/to/task.md --config profiles/dev.json
```

## Ключ организаторов
Локальные настройки: `OPENAI_BASE_URL=https://changellenge.up.railway.app/v1` и `OPENAI_MODEL=qwen/qwen3.8-27b`; реальный ключ хранится только вне Git. Командный лимит составляет 600 рублей в день со сбросом в 03:00 МСК.

## Бюджет
Боевой запуск ограничен 180 минутами, из которых 40 резервируются для финального обучения; одновременно запускаются до трёх совместимых экспериментов. Тесты используют короткие профили, а цель первого submission — 10 минут, без гарантии при медленном API.

## Скиллы
Все 17 `skills/*/SKILL.md` содержат рабочие инструкции на английском языке и manifests версии `1.0.0` со статусом `ready`. Общий контракт и базовые `candidate_sdk`, `validation`, `metrics`, `preprocessing` подключаются автоматически; библиотечные скиллы и дополнительные техники выбираются по гипотезе. Полный набор вместе с общими правилами укладывается в лимит 24 000 символов. Ограничения адаптеров и источники описаны в [docs/SKILLS.md](docs/SKILLS.md); доступность библиотек проверяется отдельно.

## Документация
[ARCHITECTURE.md](ARCHITECTURE.md) описывает каждый функциональный блок, его файлы, контракты и ограничения. [docs/STAGE1.md](docs/STAGE1.md) содержит самостоятельные команды первого этапа.

## Тесты и ZIP
Обычные тесты используют mock LLM, а обращения к реальному API выполняются отдельно. Сборщик создаёт плоский ZIP с `solution.py`, `requirements.txt` и `mlmom_bundle.py`, поскольку Boosters не переносит вложенные папки.
Проверенный [архив для загрузки](submission/mlmom-solution.zip) и [отчёт проверки](VALIDATION.md) включены в репозиторий.

```bash
python -m unittest discover -v
python scripts/package_solution.py --output dist/mlmom-solution.zip
```

## Восстановление
Укажите постоянный `--run-dir`, а после прерывания запустите ту же команду с `--resume`. Входные файлы и конфигурация должны совпадать; исходный дедлайн сохраняется.

```bash
python solution.py task.md --run-dir artifacts/task-run
python solution.py task.md --run-dir artifacts/task-run --resume
```

## Ограничения
Forecasting распознаётся, но исполнение отложено; clustering требует числового пространства оценки, anomaly detection — явных evaluation labels. Процессная изоляция ограничивает ресурсы и последствия ошибок, а независимый финальный audit holdout в v1 отсутствует.
